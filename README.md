# クリニック待合室の受付・呼び出しシミュレーター

架空のクリニックを題材にした学習用Webアプリです。受付係が受付番号を発行して順番に呼び出し、待合室の利用者は別の画面で呼び出し中の番号と待機人数を確認します。

開発を通じて、TypeScriptの基本文法を理解し、自分で書いた処理を説明できるようにします。C#／ASP.NET CoreのAPIの基本実装には生成AIを活用し、MVCの役割分担と、画面操作からAPIを経て表示が更新されるまでの流れを学びます。完成時はAzure App Serviceに公開し、PCとスマホで2つの画面を確認します。

## 初めての方はここから

1. **[要件定義](docs/要件定義.md)** で、誰が使い、何ができれば完成かを確認する。
2. **[詳細設計](docs/詳細設計.md)** で、画面イメージ、API、受付番号の状態、フォルダ構成を確認する。
3. **[AGENTS.md](AGENTS.md)** はAI作業指示書。AIに開発を頼むときに参照する。実装に着手する前に、AIが作業範囲を示してユーザーの許可を得る。

## Gitで作業する

### ブランチの切り方

最新の `master` を起点に、作業ごとにブランチを作ります。名前は **`種類/作業内容`** とし、作業内容には短い英小文字をハイフンでつなぎます。

| 種類 | 用途 | 例 |
|---|---|---|
| `feature/` | 機能の追加 | `feature/issue-ticket` |
| `fix/` | 不具合の修正 | `fix/prevent-double-call` |
| `docs/` | 資料の追加や修正 | `docs/update-readme` |

### コミットメッセージの書き方

Visual Studioの「Git 変更」画面で、「メッセージを入力してください」欄に **`種類: 何をどう変えたか`** を1行で書きます。

| 種類 | 使う場面 | 入力例 |
|---|---|---|
| `docs` | READMEや設計資料を変更したとき | `docs: READMEにコミットメッセージの書き方を追加` |
| `feat` | 機能を追加したとき | `feat: 受付番号を発行するAPIを追加` |
| `fix` | 不具合を修正したとき | `fix: 呼び出し中に次の番号を呼べる不具合を修正` |

1行目を読めば、変更した対象と内容が分かるようにします。変更の理由や確認結果も残したい場合は、1行空けて補足を書きます。

### プルリクエストの書き方

たとえば、README・AGENTS.md・設計資料をまとめて追加する場合は、次のように入力します。

**① コミットするとき**は、Visual Studioの「Git 変更」のメッセージ欄に書きます。

```text
docs: 開発ガイドと要件定義・詳細設計を追加
```

**② プッシュ後にPRを作るとき**は、GitHubの「Add a title」に変更の要約を書きます。コミットメッセージがPR全体の変更を表しているなら、同じ文言を使えます。

```text
docs: 開発ガイドと要件定義・詳細設計を追加
```

複数のコミットをまとめる場合は、各コミットに個別の変更を書き、PRのタイトルには全体の目的を書きます。

**③ 同じPR作成画面の「Add a description」**には、何を変えて何を確認したかを書きます。

```markdown
## 変更内容

- 要件定義と詳細設計を追加しました。
- READMEに開発の始め方を、AGENTS.mdにAI向けの作業ルールを記載しました。

## 確認したこと

- READMEから要件定義・詳細設計・AGENTS.mdを開けることを確認しました。
```

①のコミットメッセージは、PRを開いた後に **Commits** タブで確認できます。
