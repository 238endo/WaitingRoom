# 単体テスト（受付ルール）

**テスト技法**　ブラックボックステスト（仕様に基づくテスト）

[要件定義](../要件定義.md)と[詳細設計](../詳細設計.md)に沿って、受付状況の取得、番号発行、呼び出し、案内完了を確認する。下表の9件は、メモリ保存の単体テストとSQL保存の結合テストで共通とし、戻り値と処理後の状態を MSTest で判定する。

## 実行手順

1. Visual Studio で [WaitingRoom.slnx](../../WaitingRoom.slnx) を開く。
2. **「テスト」→「テスト エクスプローラー」** を開き、実行するグループを選ぶ。テストが表示されない場合は、先にソリューションをビルドする。
   - メモリ版の単体テストは `InMemoryQueueStoreTests` を実行する（9件）。
   - SQL版の結合テストは `SqlQueueStoreTests` を実行する（同じ9件）。準備と実行方法は[結合テスト](結合テスト.md#fr-07のsql保存の自動テスト)を参照する。
   - 両方をまとめて確認する場合は **「すべて実行」** を押す（合計18件）。
3. 緑のチェックが表示されたテストは合格。失敗した場合は、テスト名を選んで詳細に表示される期待値と実際の値を確認する。

## 必須の確認項目

| 確認項目 | 対象メソッド | 期待結果 | 確認結果 |
|---|---|---|---|
| 初期状態 | `GetSnapshotAsync` | 呼び出し中の番号がなく、待機列が空。 |  |
| 受付番号の発行 | `IssueTicketAsync` | 最初の2件は `A001`、`A002` の順で発行され、待機列にもその順で並ぶ。 |  |
| 発行順の呼び出し | `CallNextAsync` | 先に発行した番号が呼び出され、後から発行した番号だけが待機列に残る。 |  |
| 待機列が空のときの呼び出し | `CallNextAsync` | 番号は返らず、受付状況は空のまま。 |  |
| 呼び出し中にもう一度呼び出す | `CallNextAsync` | 次の番号は返らず、呼び出し中の番号と待機列は変わらない。 |  |
| 案内完了と次の呼び出し | `CompleteTicketAsync` | 1件目を完了すると呼び出し中の番号が消える。次を呼ぶと待機中だった2件目が呼び出される。 |  |
| 待機中の番号の案内完了 | `CompleteTicketAsync` | 完了を受け付けず、呼び出し中の番号と待機列は変わらない。 |  |
| 未発行の番号の案内完了 | `CompleteTicketAsync` | 番号が見つからないという結果が返り、受付状況は変わらない。 |  |
| 案内完了済みの番号の再完了 | `CompleteTicketAsync` | 再度の完了を受け付けず、受付状況は変わらない。 |  |
