# 結合テスト（操作確認）

4つの受付 API の応答と、受付画面での操作が待合室画面に反映されることを確認する。「第2版の確認」より前の手順は、メモリに受付データを保存する初版が対象。

## ローカルでの起動手順

1. Visual Studio で [WaitingRoom.slnx](../../WaitingRoom.slnx) を開く。
2. ソリューション エクスプローラーで `WaitingRoom.Web` を右クリックし、**「スタートアップ プロジェクトに設定」**を選ぶ。
3. 上部の構成で **`Debug`**、緑の再生ボタン横の起動プロファイルで **`https`** を選び、**`F5`** で起動する。
4. アプリがすでに動いていて、受付データを空にする必要がある場合は、**`Shift + F5`** で停止し、**`F5`** で起動し直す。アプリを停止すると、メモリに保存していた受付データが初期化される。

## API の確認（ローカル）

1. [ローカルでの起動手順](#ローカルでの起動手順)に沿ってアプリを起動し、Visual Studio で [WaitingRoom.Web.http](../../WaitingRoom.Web.http) を開く。
2. 表の手順にある `GET` または `POST` と URL の末尾（例 `/api/tickets`）が一致するリクエストを探す。案内完了の `POST /api/tickets/{number}/complete` では、URL の受付番号を表で指定された番号に置き換える。
3. リクエストの上にある **「要求の送信」** を押し、応答欄で結果を見る。

リクエストを続けて送るときは、前の応答が表示されてから次のリクエストを送信する。

## 第2版の確認

Azure SQL Database に保存する環境では、再起動しても受付データが残る。空の状態が必要なケースでは、受付番号の履歴が空で最後の発行番号が0のテスト用データベースを用意する。集計のケースでは、同じテスト用データベースに Web アプリと Function App を接続する。

| 区分 | 確認項目 | 前提条件 | 手順 | 期待結果 | 確認結果 |
|---|---|---|---|---|---|
| 正常系 | FR-06 待合室の自動更新 | FR-06 を入れた Web アプリが起動し、待機人数が0人。 | 1. 受付画面と待合室画面を別ウィンドウで開く。<br>2. 受付画面で番号を1件発行する。<br>3. 待合室画面で次の自動更新を待つ。 | 待合室画面の「更新」を押さなくても、待機人数が0人から1人になる。 |  |
| 正常系 | FR-07 再起動後の受付状況 | 空のテスト用データベースに接続した Web アプリが起動している。 | 1. 受付画面で番号を3件発行する。<br>2. 「次を呼ぶ」を1回押す。<br>3. Web アプリを再起動して受付画面を開く。<br>4. 番号をもう1件発行する。 | 再起動後も `A001` が呼び出し中で、`A002`、`A003` がその順で待機している。次の発行番号は `A004`。 |  |
| 正常系 | FR-08 日次集計の結果表示 | Web アプリと Function App が同じテスト用データベースを使っている。テスト用タイマーは1分間隔。 | 1. 集計対象となる日本時間の前日に2件、当日に1件の発行履歴を用意する。<br>2. タイマーの実行をログで確認する。<br>3. 受付画面を開く。 | 前日の集計は2件と表示される。集計結果が保存されていない日は「集計結果なし」と表示される。 |  |

## FR-07のSQL保存の自動テスト

MSTest の `SqlQueueStoreTests` では、[単体テストの必須確認項目](単体テスト.md#必須の確認項目)と同じ9件をSQL保存で確認する。各テストは Windows の SQL Server Express LocalDB に専用のデータベースを作り、`001-create-queue-tables.sql` で受付テーブルを用意する。実行が終わったら、そのテストが作ったデータベースを削除する。

Visual Studioのテスト エクスプローラーで `SqlQueueStoreTests` を実行するか、リポジトリのルートで次を実行する。

```powershell
dotnet test WaitingRoom.slnx --filter FullyQualifiedName~SqlQueueStoreTests
```

公開先の App Service と Azure SQL Database の接続は、公開後の操作確認で行う。初期化SQLの確認手順は[詳細設計の開発用DBの初期化](../詳細設計.md#開発用dbの初期化)を参照する。
