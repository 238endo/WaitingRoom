# 結合テスト（操作確認）

受付画面での操作が API を通じて受付状況を更新し、待合室画面にも反映されることを確認する。

## Azure での操作確認

Azure App Service に公開した同じアプリを、PC の受付画面とスマートフォンの待合室画面で開く。各操作のあとに待合室画面を更新して確認する。

| 操作 | 期待する結果 | 結果 |
|---|---|---|
| PC で「受付番号を発行」を1回押す。 | 受付画面の待機列に発行した番号が追加され、待合室画面の待機人数が1人増える。 | 確認済み |
| PC で「次を呼ぶ」を1回押す。 | 両画面に同じ呼び出し番号が表示され、待合室画面の待機人数が1人減る。 | 確認済み |
| PC で「案内完了」を押す。 | 待合室画面に「呼び出し中の番号はありません」と表示され、待機人数は変わらない。 | 確認済み |

「確認済み」は、公開後に PC とスマートフォンで行った操作についての記録。

## 追加の操作確認

番号を `A001` から確認する場合は、ローカルのアプリを起動し直して受付データを初期化する。各項目の前に、手順に記載した状態を用意する。

| 操作 | 期待する結果 | 結果 |
|---|---|---|
| 初期状態で「受付番号を発行」を2回押す。 | 受付画面の待機列に `A001`、`A002` がこの順で表示される。 | 未確認 |
| `A001`、`A002` が待機している状態で「次を呼ぶ」を押し、待合室画面を更新する。 | 両画面に呼び出し中の番号として `A001` が表示され、待合室画面の待機人数が1人になる。 | 未確認 |
| `A001` が呼び出し中で `A002` が待機している状態で「案内完了」を押す。続けて「次を呼ぶ」を押し、待合室画面を更新する。 | 呼び出し番号が `A002` に切り替わり、待合室画面の待機人数は0人になる。 | 未確認 |
| 待機列が空のときと、呼び出し中の番号があり次の番号が待機しているときに、受付画面を確認する。 | どちらの場合も「次を呼ぶ」が無効になる。 | 未確認 |
| 待機番号を2件用意して、受付画面を2つ開く。片方で「次を呼ぶ」を押したあと、更新していないもう片方でも「次を呼ぶ」を押す。 | 2回目のリクエストは HTTP `409` になり、先頭の番号が呼び出し中のままで、次の番号は待機列に残る。 | 未確認 |
| 待機番号を2件以上用意して、2つの受付画面からほぼ同時に「次を呼ぶ」を押す。 | 先頭の1件だけが呼び出し中になり、残りは発行順のまま待機列に残る。 | 未確認 |
