# 単体確認（内部処理）

[InMemoryQueueStore.cs](../../WaitingRoom.Web/Stores/InMemoryQueueStore.cs) のメソッドを直接呼び出して、番号の発行順や受付状態がルールどおりに変わるかを確認する。`QueueService` はこれらの処理をストアに依頼し、ストアが返した結果を受け取る。

各項目で新しい `InMemoryQueueStore` を用意し、手順どおりにメソッドを呼び出す。呼び出しには `CancellationToken.None` を渡し、各メソッドの結果は `await` で受け取る。状態を確認するときは `GetSnapshotAsync` を呼び出し、呼び出し中の番号と待機列を見る。

| 確認項目 | 手順 | 期待する結果 | 結果 |
|---|---|---|---|
| 初期状態 | `GetSnapshotAsync` を呼ぶ。 | 呼び出し中の番号は `null` で、待機列は空。 | 未実施 |
| 受付番号の発行 | `IssueTicketAsync` を2回呼ぶ。 | 1回目は `A001`、2回目は `A002` が返り、待機列にもこの順で入る。 | 未実施 |
| 発行順の呼び出し | 2件発行し、`CallNextAsync` を1回呼ぶ。 | `A001` が返って呼び出し中になり、待機列には `A002` だけが残る。 | 未実施 |
| 待機番号がない場合 | 初期状態で `CallNextAsync` を呼ぶ。 | `null` が返り、呼び出し中の番号と待機列は変わらない。 | 未実施 |
| 呼び出し中の再呼び出し | 2件発行し、`CallNextAsync` を2回呼ぶ。 | 2回目は `null` が返り、`A001` は呼び出し中、`A002` は待機中のまま。 | 未実施 |
| 案内完了と次の呼び出し | 2件発行して `A001` を呼び出す。`CompleteTicketAsync` に `A001` を渡し、状態を確認してから `CallNextAsync` を呼ぶ。 | 案内完了は `Completed` が返り、呼び出し中の番号が `null` になる。次の呼び出しで `A002` が返り、待機列が空になる。 | 未実施 |
| 待機中の番号の案内完了 | 2件発行して `A001` を呼び出し、`CompleteTicketAsync` に待機中の `A002` を渡す。 | `NotCalling` が返り、`A001` は呼び出し中、`A002` は待機中のまま。 | 未実施 |
| 未発行の番号の案内完了 | 初期状態で `CompleteTicketAsync` に `A001` を渡す。 | `NotFound` が返り、呼び出し中の番号と待機列は変わらない。 | 未実施 |
| 案内完了済みの番号の再完了 | `A001` を発行、呼び出し、案内完了したあと、もう一度 `CompleteTicketAsync` に `A001` を渡す。 | 2回目は `NotCalling` が返り、呼び出し中の番号と待機列は変わらない。 | 未実施 |
