# クリニック待合室の受付・呼び出しシミュレーター 要件定義

## 目的と対象範囲

架空のクリニックの窓口で、受付係が番号を発行し、受付順に利用者を呼び出す。待合室の利用者は、自分の番号が呼ばれているかを画面で確認できる。

初版は窓口1つの学習用デモとする。利用者の識別には架空の受付番号だけを使う。PCの受付画面とスマホの待合室画面を、それぞれ専用のURLで開いて使用する。

## 今回の学習目的

- TypeScriptの基礎文法を学び、コードの内容を理解し、自分の言葉で説明できるようにする。
- MVC構成で各部分がどんな役割を持ち、リクエストから応答まで処理がどう進むかを説明できるようにする。
- Azure App Serviceの役割を理解し、Web APIを試験的に公開して、接続と動作を確認できるようにする。

## 利用者と画面

| 利用者 | 画面 | できること |
|---|---|---|
| 受付係 | 受付画面 | 受付番号を発行する。待機列を確認し、次の番号の呼び出しと案内完了を操作する。 |
| 待合室の利用者 | 待合室画面 | 現在の呼び出し番号と待機人数を確認する。「更新」で最新の状況を取得する。 |

## 機能要件

| ID | 機能 | 要件 |
|---|---|---|
| FR-01 | 受付番号を発行する | 「受付番号を発行」を押すと、`A001` から順に重複しない番号を発行し、待機列の末尾に追加する。 |
| FR-02 | 受付状況を確認する | 受付画面には呼び出し中の番号と、発行順に並んだ待機番号を表示する。受付画面で操作が成功したら、その結果を画面に反映する。 |
| FR-03 | 次の番号を呼ぶ | 待機列に番号があり、呼び出し中の番号がないときに「次を呼ぶ」を押せる。押すと、待機列の先頭の番号が「呼び出し中」になり、待機列から外れる。複数の受付画面から同時に操作しても、呼び出し中は全体で1件までとする。 |
| FR-04 | 案内を完了する | 現在呼び出し中の番号に対して「案内完了」を押すと、その番号は「案内完了」になる。次の待機番号は、受付係が「次を呼ぶ」を押したときに呼び出す。 |
| FR-05 | 待合室で最新状況を確認する | 待合室画面を開いたときと「更新」を押したときに、最新の呼び出し番号と待機人数を表示する。待機人数は「待機中」の件数とする。呼び出し中の番号がないときは、そのことが分かる表示にする。 |

受付番号は **待機中 → 呼び出し中 → 案内完了** の順に状態が変わる。初版の受付データはアプリの稼働中に保持し、アプリを再起動すると初期化する。
